# 现代内核底座与 TUN 模式：Sing-box & Mihomo

> “有了优秀的传输协议，还需要一个强大的路由核心与流量调度引擎。现代工具的竞争，早已从协议本身延伸到了系统底层流量调度与 DNS 掌控能力。”

在以前，使用代理非常痛苦：
* 打开了代理软件，浏览器能上网了，但**终端里的 `curl`、`git clone` 依然超时报错**；
* 命令行需要繁琐地手动设置 `export http_proxy=...` 和 `export https_proxy=...`；
* 遇到不支持代理配置的命令行工具、后台守护进程或者游戏客户端，就只能干瞪眼。

现代科学上网生态通过两大核心技术彻底终结了这种割裂感：
1. **统一全能的现代内核底座（Sing-box & Mihomo）**；
2. **操作系统内核级的网络虚拟接管（TUN 模式）与 Fake-IP 体系**。

---

## 一、现代内核双雄：Sing-box 与 Mihomo

在 2023 年开源界经历了一波清洗与重组后，两套新一代核心成为了几乎所有现代客户端（如 Clash Verge Rev、GUI.for.SingBox、Flclash 等）的标准底层引擎：

```
+-------------------------------------------------------------------------+
|                  GUI 客户端 (Clash Verge Rev / Flclash / NekoBox)       |
+-------------------------------------------------------------------------+
                                    |
                    +---------------+---------------+
                    |                               |
          [ Sing-box 内核 ]               [ Mihomo (Clash Meta) 内核 ]
          * Go 语言重写，追求极简内存占用  * 继承并深度演进 Clash 规则体系
          * 原生支持全协议 (Reality/Hy2)  * 对分流规则集、GEOIP、脚本支持极强
          * 设计现代、无历史包袱          * 拥有全网最成熟丰富的前端 UI 生态
```

### 1. Sing-box（通用代理平台的新标杆）
由 Nekoray 原作者开发，被誉为代理界的“Swiss Army Knife（瑞士军刀）”：
* **原生全能**：原生且第一时间支持 Shadowsocks、VMess、VLESS (Reality)、Trojan、Hysteria 1/2、TUIC、WireGuard、SSH、ShadowTLS 等所有主流与前沿协议；
* **极速与低资源**：纯粹的 JSON 架构，代码极度轻量精简，路由匹配性能极高，特别适合路由器（OpenWrt）和小内存设备。

### 2. Mihomo（前身为 Clash.Meta）
在原版 Clash 闭源删库后，由社区主力维护并持续演进的核心：
* **规则生态无可替代**：完美兼容经典的 YAML 订阅配置，拥有全球最丰富的域名分流规则库（Domain Rule Provider）；
* **功能进化**：全面补齐了 VLESS-Reality、Hysteria 2、TUIC 等现代协议，内置强大的 DNS 分流引擎。

## 二、TUN 模式：终结“终端不走代理”的终极解法

### 1. 传统系统代理（System Proxy）的局限
以前我们在代理软件中点击“设为系统代理”，本质上只是**修改了操作系统的网络环境注册表/配置文件**，告诉系统：“建议 HTTP/HTTPS 流量走 `127.0.0.1:7890`”。
* **破绽所在**：这种方式完全靠客户端软件自觉！
  * Chrome、Edge 等浏览器会自觉读取这个配置；
  * 但 Mac/Linux 终端（Terminal）、`git`、`ssh`、Docker 守护进程、Go/Python 脚本直接调用 Socket 发包，**根本不理睬系统代理配置**！

### 2. TUN 模式（虚拟网卡接管）的工作原理
TUN 是操作系统内核层面提供的 **虚拟网络设备（Network TUNnel）**。

```
[应用程序 (Chrome / Terminal / Git / Docker / 游戏)]
                      │ (所有数据包无论是否配置代理)
                      ▼
[操作系统内核协议栈 (IP 数据包路由表)]
                      │ (路由表默认网关指向虚拟网卡)
                      ▼
            ┌───────────────────┐
            │   utun / wintun   │ (TUN 虚拟网卡设备)
            └─────────┬─────────┘
                      │ (直接提取原始三层 IP 数据包)
                      ▼
         [ Sing-box / Mihomo 代理内核 ]
       (执行规则分流: 遇到 Google 走节点, 遇到 Baidu 直连)
                      │
            ┌─────────┴─────────┐
            ▼                   ▼
      [ 代理节点加密发送 ]     [ 真实物理网卡直连 ]
```

* 开启 TUN 模式后，代理软件会向操作系统注册一张**虚拟物理网卡**（例如 Windows 的 `wintun`，macOS 的 `utun`）；
* 软件修改系统的**内核路由表（Route Table）**，将默认网关直接指向这张虚拟网卡；
* **彻底解放**：不管是终端命令行、自写脚本、还是后台程序，发出的每一个 IP 数据包都会被强制无差别送入代理核心进行规则分流，**彻底无需再配置任何终端环境变量！**

## 三、Fake-IP：防 DNS 污染与秒级建连的黑科技

在 TUN 模式中，最精妙的设计莫过于 **Fake-IP 模式**。

### 1. 传统 DNS 解析（Redir-Host）的弊端
当你访问 `google.com` 时：
1. 你的电脑必须先向本地 DNS 发出查询请求：“请问 `google.com` 的 IP 是什么？”
2. 这个 DNS 请求直接被 GFW 拦截并污染，返回一个假 IP（或者海外 DNS 查询等待 200ms 握手）；
3. 即使代理软件最后帮你中转，本地也早已遭受了 DNS 污染或者忍受了高昂的查询延迟。

### 2. Fake-IP 的魔法运作
在现代内核（Mihomo / Sing-box）的 Fake-IP 模式下：

```
1. 本地程序向系统询问: "google.com 的 IP 是多少?"
                        │
                        ▼
2. 现代代理内核瞬间直接回答: "是 198.18.0.25 !" (在内核内存中随机分配一个保留网段的假 IP)
   - 本地程序立刻拿到结果，用时 0 毫秒！无需任何网络请求！
                        │
                        ▼
3. 本地程序向 198.18.0.25 发起 TCP 连接
                        │
                        ▼
4. 数据包进入 TUN 虚拟网卡，被代理内核截获
   - 代理核心查内存映射表: "198.18.0.25 对应的是谁? 哦，是 google.com!"
   - 代理核心直接打包向远端代理服务器发送: "帮我建立到域名 google.com 的隧道"
                        │
                        ▼
5. 远端境外 VPS 代为进行真实的 DNS 解析并返回数据
```

* **三大绝佳优势**：
  1. **完全免疫国内本地 DNS 污染与 DNS 泄露**；
  2. **连接速度极大提升**：本地省去了昂贵的跨海 DNS 解析耗时，网页瞬间建立连接；
  3. **域名级别的精准分流**：由于代理软件在最后一步直接拿到原始域名，能够 100% 准确命中分流规则。

## 四、现代开发者的日常配置建议

对于工程师、学生或内容创作者，目前体验最佳的日常姿势推荐：

1. **核心引擎选择**：
   * 喜欢现代化美观 UI、开箱即用规则分流：首选 **Clash Verge Rev**（基于 Mihomo 内核）；
   * 追求极简、跨平台全协议支持：首选 **Sing-box 官方 GUI** 或 **GUI.for.SingBox**。
2. **开关配置**：
   * 勾选 **开启 TUN 模式（TUN Mode）**；
   * DNS 模式选择 **Fake-IP**；
   * 关闭繁琐的手动环境变量配置，享受整机全透明分流。
