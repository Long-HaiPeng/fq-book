# 基于 UDP/QUIC 的抗弱网协议：Hysteria 2 与 TUIC

> “如果底层物理网络充满丢包，那么传统的 TCP 拥塞控制就成了最大的自废武功；现代抗审查协议选择用 UDP 和自研拥塞控制撕破限制。”

在很多时候，阻碍你顺畅访问互联网的不仅是 GFW 的审查拦截，还有**恶劣的国际出口网络环境**：
* 晚高峰跨海光缆丢包率高达 15% ~ 30%；
* 许多便宜的境外 VPS 走的是普通国际线路，网络延迟高且抖动剧烈；
* 即使使用了 Shadowsocks 或 Reality，看 YouTube 依然卡在缓冲转圈，测速只能跑几兆。

为什么会这样？**问题出在传统的 TCP 协议本身。**

为了彻底解决高丢包网络下的速度暴跌，以 **Hysteria 2** 和 **TUIC** 为代表的新一代基于 **UDP / QUIC** 的协议应运而生。

---

## 一、传统 TCP 代理在跨境网络下的痛点

要理解 Hysteria 2 的威力，首先要搞清 TCP 在国际长距离网络中的两大致命弱点：

### 1. 队头阻塞（Head-of-Line Blocking）
TCP 是严格保证数据包顺序交付的可靠传输协议。如果编号为 #3 的数据包在太平洋海底光缆中丢了，那么哪怕 #4 到 #100 号数据包都已经安全抵达你的电脑，操作系统内核也**必须强制卡住所有应用层数据**，等待 #3 重传成功。
这在单连接多路复用时，会导致一个页面的小图标丢包拖垮整个浏览器的所有请求。

### 2. 保守的 TCP 拥塞控制机制（丢包退避）
经典的 TCP 拥塞控制算法（如 Cubic、Reno 等）设计于几十年前，它们有一个默认假设：**丢包 = 网络堵塞了**。
只要一旦发现丢包，TCP 就会主动将发送窗口腰斩（减半），大幅降低发送速度。
* 然而在跨境公网上，**丢包往往只是物理光缆质量差或路由抖动，带宽本身其实非常宽裕**；
* 标准 TCP 的“自我阉割”，直接导致你的百兆甚至千兆宽带在跨境时只能跑出几百 KB/s 的龟速。

---

## 二、现代解决方案：转向 QUIC 与 UDP

HTTP/3 的核心基石是 **QUIC（基于 UDP 的多路复用传输协议）**。Hysteria 2 与 TUIC 正是站在了这一全新通信底座之上：

```
传统架构:    [应用流量] ──> [TLS 加密] ──> [TCP 传输层] ──> [IP 网络层] (容易队头阻塞、丢包断崖减速)
现代架构:    [应用流量] ──> [TLS 1.3] ──> [QUIC / UDP] ──> [IP 网络层] (无队头阻塞、独立流、可定制算法)
```

1. **多流独立**：每个数据请求是完全独立的流（Stream），任何单个流的丢包不会波及其他连接。
2. **0-RTT 极速握手**：TUIC 和 Hysteria 2 深度利用 QUIC 的 0-RTT/1-RTT 机制，极大地降低了建连延迟。

---

## 三、Hysteria 2 的杀手锏：Brutal 拥塞控制与端口跳跃

**Hysteria 2**（中文常被称作“歇斯底里”）是目前抗弱网能力最强的代理协议之一。

### 1. Brutal 拥塞控制算法（无视丢包的强制推流）
与标准 TCP 遇到丢包就退避减速截然相反，Hysteria 2 自研了 **Brutal** 算法：
* 服务端与客户端约定一个预设带宽（例如你的宽带下行是 300Mbps，上行是 30Mbps）；
* 发送端**不管网络中间丢了多少包，始终按照约定的速率持续推流发包**，丢失的包由接收端单独请求补发；
* **实测结果**：在即使高达 25% 恶劣丢包率的网络下，Hysteria 2 依然能把 VPS 的下行带宽跑出 90% 以上的惊人速度，4K/8K 视频直接秒开。

### 2. 端口跳跃（Port Hopping / 端口跳变）
国内部分地区运营商（ISP）的防火墙会对持续占用大带宽的境外单 UDP 端口进行恶意的 **QoS 限速或直接丢包阻断**。
Hysteria 2 支持配置一个端口范围（例如 `20000-40000`）：
* 客户端和服务器在通信过程中，会按照预定算法在毫秒级别**动态跳变通讯端口**；
* 运营商的防火墙根本无法锁定某一个端口进行持续限流，有效瓦解针对 UDP 的 QoS 限制。

### 3. 原生 HTTP 认证与流量伪装
Hysteria 2 彻底重写了传输结构，伪装成标准互联网最常见的 HTTP/3 流量，支持原生密码鉴权与伪装页面回显。

---

## 四、TUIC 协议：轻量原生的 QUIC 代理

**TUIC** 是另一个基于原生 QUIC 协议的高性能代理方案。

* **与 Hysteria 2 的区别**：
  * Hysteria 2 的 Brutal 算法具有“侵略性”（不管丢包强制推流，有点像多车道强行超车）；
  * TUIC 更偏向于**遵从原生标准 QUIC 规范**，使用 BBR 拥塞控制，协议开销更小、资源占用更低、对服务器 CPU 要求更友好。
* **适用场景**：适合配置较低的小内存 VPS（如 256MB~512MB），或者在网络环境相对稳定但注重连接延迟和多路复用的场景。
